# DVD 纹理色卡（第三版，模拟）

[English](README.md)

一套 A3 色卡，画出 637 种 DVD 纹理在不同观察角度下的预测颜色。这里的"纹理"是沿轨道重复写入的一小段字节（`spec` 列，十六进制，例如 `A37062`）。重复写入会沿轨道形成周期性的凹坑排列，像光栅一样把光分成颜色。

**这些颜色是模型预测。还没有任何一张实刻盘验证过；只有第 1 页做过原尺寸人工检查。**

| 文件 | 内容 |
|---|---|
| [`texture_cards_v3_led.pdf`](texture_cards_v3_led.pdf) | 四页合集，白光 LED 照明（主版本） |
| [`texture_cards_v3_d65.pdf`](texture_cards_v3_d65.pdf) | 同样四页，D65 日光 |
| `data/palette_merged.json` | 输入：637 种纹理的 ID、spec、周期、实测块纯度，按页分组 |
| `data/<页>_<led\|d65>_manifest.json` | 每行一条记录（ID、spec、周期 µm、空间频率、在页面上的位置），以及该页的固定曝光 |
| `scripts/` | 生成脚本，按我们实际运行时的样子发布（见下） |
| `checks/` | 复现对照、物理自检、模型和源文件哈希 |

## 怎么看

- 每行是一种纹理。横轴是 δ（0.10–0.95），表示观察几何：δ = sin θ入 + sin θ出，沿轨道方向取分量。周期为 P（µm）的图案送到眼睛的波长是 λ = 1000 · P · δ nm，所以沿一行往右看，相当于把盘慢慢倾斜。δ 是方向分量之差，不是角度。
- `P` 是周期（µm），`1/P` 是每毫米线数。
- 黑色段表示一阶衍射落在 380–780 nm 之外，旁边标的是紫外或红外端的波长。每行上方的细条画的是全部阶次。

## 颜色怎么算的

1. 用真实的 EFMPlus 编码器（含 DVD 扰码和 DSV 控制）把纹理编成通道位，按整个 ECC 块求功率谱。
2. 通道位换成凹坑：假设凹坑宽 W = 0.35 µm、边缘模糊 σ = 0.03 µm、长度不变（ΔL = 0）。
3. 对灯的光谱、CIE 1931 2° 观察者、有限大小的灯和眼睛积分：灯直径 5 cm、距离 1 m，瞳孔 4 mm、距离 30 cm，沿轨道对称几何。
4. XYZ 转 sRGB，每页每种灯一个固定曝光，不逐行提亮，所以同一页内亮度可以互相比较。

LED 光谱是名义上的解析白光 LED（450 nm 和 560 nm 两个高斯峰），不是实测灯。CIE 表是 5 nm 间隔的转录，没有和官方 1 nm 文件核对过。

## 运行脚本

脚本按我们实际运行时的样子发布。它们会导入本仓库的 `discprobe.efmplus`、`discprobe.dvd` 和 `tools/dsv_block.py`；`scripts/wave_model.py` 开头的 `ROOT` 和 `scripts/make_cards.py` 开头的源文件、字体路径指向我们自己的目录，运行前要改。需要 Python 3.13、NumPy、Pillow，不用 GPU 和网络。637 条全部重算，两个进程约 20–30 分钟。

```
python render_all.py --estimate          # 只估时间
python render_all.py --layout-check      # 只查排版，不算颜色
python render_all.py --sheets 1          # 第 1 页，两种灯
python render_all.py --sheets all --lamps LED
```

## 局限

- 全部是模拟，没有实刻、实拍验证。
- 只适用于 DVD。蓝光用 17PP 编码、通道位 74.5 nm，这套色卡不能直接用，但同样的计算流程可以。
- 色卡能比较给定 δ 下的可见范围和色相，不能预测照片里的绝对亮度、二阶效率、印刷颜色，也不能说明光驱能否读出这张盘。
