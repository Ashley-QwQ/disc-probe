## 背景（用户 11-20 截图，走查清单 `D:/dp-dev/cards/real-walk-1119.md` 第 29 条）

光驱里是一张已经封盘的盘，报成 DVD-ROM。新建作品页上看到的是：

- 页面只写了一句中性的"The drive recognised DVD-ROM"；
- 转盘照样选在 DVD-R，因为 `firstSub()` 碰到 ROM 时退回 `-R`；
- 批次自动填成上一批 RITEKF1；
- "Next: add a picture"照样能点。

`readDrive()` 只看 `media`，不看盘是不是空白、有没有封盘。这和用户批评 DIS 的毛病一样："光驱面板已经读到盘的状态，页面却什么都没说"。

## 要做的

1. **把光驱里的盘说清楚**：`api.readDisc()` 返回的信息里（看 core 的 `info` 输出，以及 webui 读盘接口实际返回的字段）如果有"是否空白 / 已写入 / 已封盘 / 可擦写 / ROM"这些状态，就在批次下方用人话说出来，中英文都要有，中文沿用仓库现有的说法。例如：
   - 空白盘：保持现在的说法，再带上 MID。
   - 已写入或已封盘：写"光驱里这张盘已经刻过，不能再刻图案。现在设计没关系，刻之前换一张空白盘。"
   - 可擦写盘且上面有数据：写"这张可擦写盘上有数据，刻之前要先擦除。"擦除要看 core 有没有现成的路，没有就只提示。
   - 读不到状态：照实写"没读出这张盘是不是空白的"，不要猜。

   这里只给提示，**不拦设计**：作品可以先做，到刻录时再换盘。拦刻录归 burn-gates 卡管，这张卡不做。
2. **转盘和批次不要被一张不能用的盘带偏**：
   - 光驱里的盘不是空白可刻的（ROM、已封盘、已写入）时，转盘不要自动转到它的类型和子类型，批次也不要据它推荐或新建；
   - 改为沿用"光驱里没有盘"时的逻辑（上一批 / 最近用过的）。
3. **批次可以"先不选"**：批次框要能留空，或者选"稍后再定"。留空时：
   - "下一步"仍然能进编辑器；
   - 编辑器里要说明"还没选盘的批次，先按名义参数画，刻之前要选好批次"；可画范围用该介质的名义范围或现有默认，**不要假装已经标定过**。
   - 刻录前（作品刻录页或导出镜像时）如果还没选批次，要拦下来，让人先选。这一步如果要改刻录页，只加最小的入口检查，改动写进报告，因为 burn-gates 也在改刻录页。
   - 先看现有数据结构能不能表达"没有批次"。如果需要 core 配合，或者会改到 `.dp` 作品文件的格式，只能**新增字段**，旧作品必须照原样读出来。
4. **测试**：用 Disc Lab 造这几种情况，每种都确认页面说的话对，转盘和批次的行为对：
   - 空白 DVD-R（RITEKF1）
   - 已封盘的 DVD（报成 ROM）
   - 已写入但没封盘
   - 有数据的 RW
   - 空托盘
   - 托盘开着

   另外再加一个"批次留空 → 编辑器 → 刻录前被拦"的流程测试。相关 pytest 和全部 `tests/test_*.mjs` 都要通过。
