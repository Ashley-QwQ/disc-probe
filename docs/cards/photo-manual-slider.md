## 背景

- 拍照自动校准（`discprobe/pcal.py`，读取器已冻结，SHA `d6375fae…`）随手拍时经常拒答。PCAL-E 模拟里，单张读对只有 11–15%，拍 3 张至少一张读对也只有 19–31%。
- 现在读不出时的退路：DVD 可以跳过；CD 只能导出 DIS 预设，去 DIS 里做精校准。手动填沿轨常数只能用命令行 `image --along-track-frames N`，网页上填不了。
- 用户 11-20 定了人工退路的做法：**不要用鼠标描线**（"鼠标画线没人画得好"），**学 DIS 那样加滑块，拖到对齐为止**。

## 目标

在网页拍照页（`photocal.js`）上，读取器拒答或者用户不放心时，给一个"手动对齐"模式：

1. 在用户的照片上叠一层**预测图**：按当前几何和一个假设的 L，把标靶上的径向辐条和特征画在照片的透视里（读取器第 1、2 步已经求出盘缘和圆环的单应，直接用）。
2. 提供**滑块**：
   - **沿轨常数 L**：它会让辐条随半径扭转（τ = c + L/r），这是主滑块；
   - **整体转角 c**：负责让预测图转到和照片对上。
   滑块要能精细调：键盘方向键微调、Shift 粗调，范围和步长按 DVD 和 CD 各自的物理量来定。
3. 拖动时预测图**实时**跟着扭，用户凭眼睛判断辐条和照片里的亮暗边界对没对上。参考拍照页现有的放大镜和小地图。
4. 把定下的 L 交给 core（core 现有的 `--along-track-frames` 和 photo_l 写入路径，**网页不自己算**），存进预设。要标明来源是"人工滑块"，和自动读出的、命令行填的区分开。
5. 人工值也要有**护栏**：对齐得好不好，给出一个客观读数，例如预测图和照片边缘的相关度，或者用读取器的投票函数在这个 L 处打分。差得明显时提示"可能没对准"，但不硬拦（"网页给小白，core 放开"）。
6. 命令行也要有等价的路，不能只做在网页上：例如 `photo --manual-l <mm>` 写入同样的记录，或者其他在 core 里能用的方式（"core 全功能"）。
