## 背景

这两天 DIS Discord 上至少四个人（Jake、Azul-la、Lia、SLJ）卡在同一个地方：刻了一张盘，"啥也没有"，或者只有一圈圈的环，然后跑来问。实际原因各不相同：

- 数据根本没写进去，或者把镜像当普通文件烧进了光盘；
- 从正上方看、在房间灯下看，看的角度不对；
- 没有标定，几何不对，图被沿圆周抹成一圈圈的环；
- CD-R 本身就很淡，CD-RW 更淡；
- 超薄光驱供电不足，读写不稳。

DP 用 `burn` 刻完后，本来就会抽样读回、和镜像比对（`burner.py`，结果写进 `.burn.jsonl` 的 `verification`）。用户的想法是：**这一步要复用起来**。另外，用 DIS 或别的软件刻的盘，DP 也应该能查。

## 目标

1. **core 新命令**（名字你定，比如 `checkburn`），对光驱里已刻好的盘做只读检查，不写盘：
   - 盘的状态：空白、已刻、刻了多少（最后一个 LBA 加一，和空白容量比）、是否封盘；
   - **是不是当文件烧进去的**：读文件系统根目录，盘上如果只有一个或几个 `.iso`/`.png`/`.jpg` 这类文件，并且没有图案数据的特征，就判定"把镜像当文件烧了"，说明怎么正确刻；
   - **数据对不对**：给了 `--iso` 时，复用 `burn` 的抽样读回比对，同一套代码、同一套报告格式；没给 ISO 时，至少说清盘上是随机数据、图案数据还是普通文件（`content.is_random` 等现有判断能用的就用）；
   - 有对应的 DP 刻录记录（`.burn.jsonl`）时，直接读出当时的读回结果，不必重读；
   - 最后输出一张**检查单**，每项写明"已排除 / 可能 / 没法自动判断"：
     - 数据没写进去或刻坏了：能自动判断；
     - 当文件烧了：能自动判断；
     - 看的角度：没法自动判断，给出看的方法（关灯、手电放在眼睛旁边、倾斜 20–30°、背对吸顶灯），链接到新手引导里"光怎么变成图"那几张示意；
     - 没标定或几何不对：能查就查，比如这批盘有没有标定记录、用的是不是 DIS 名义预设；
     - 盘的类型：CD-R、CD-RW 偏淡，DVD-R、DVD+R 最亮；
     - 光驱：超薄 USB 光驱提示换后面的 USB 3.0 口或加供电，读写时降速。
   - 支持 `--json`，给 agent 用。中英文提示都要有，中文用仓库现有的说法。
2. **网页入口**：刻完页（`afterburn.js`）加一个"看不到图？"入口，背后调用上面的 core 命令，显示检查单。网页上不能有只属于网页的判断逻辑。
3. **排错检索**：在 `discprobe/data/troubleshoot.json` 里加"刻完啥也没有 / nothing shows / just circles / only rings / looks like normal data"这类条目，每条都要标注依据出处（现有测试会核对出处是否真实存在），并指向新命令。考题加上这几种问法，还有社区里几句原话，例如 Jake 的"comes back looking like a cd with information on it, no distorted design"、Lia 的"Circles it is"。

## 验收

- 在 Disc Lab 上覆盖这几种情况：
  - 正常刻好的图案盘；
  - 刻到一半停了；
  - 空白盘；
  - **当文件烧进去的盘**（用 Disc Lab 造一张只含一个 ISO 文件的数据盘；造不出来就用单元测试模拟文件系统）；
  - 随机测量盘；
  - DP 有刻录记录的盘，以及没有记录的盘。
  每种情况的检查单结论都要对。
- 不改任何现有输出：`burn`、`info` 的输出逐字节不变。新命令和网页入口是新增的。
